# v2 전면 재구성안 — "바이올린 연습 파트너"

> 상태: **진행 중 (v2 브랜치)** · 1단계 뼈대 ✅ · 2단계 튜닝 ✅ · 3단계 연습 ✅ · 4단계 지판·기록 ✅

## 0. 왜 다시 만드나 (v1에서 실제로 걸리는 점)
| 문제 | 원인 | 체감 |
|---|---|---|
| 앱 시작이 느림 | 폰에서 매번 Babel(3MB)로 JSX를 변환 | 로딩 화면 1~2초 |
| 첫 실행에 인터넷 필요 | Tailwind를 CDN에서 받음 | 오프라인 첫 실행 시 디자인 깨짐 |
| 음정 분석이 화면과 같은 스레드 | 분석을 requestAnimationFrame에서 실행 | 화면이 무거우면 바늘이 끊김, 배터리 |
| 파일이 커지며 실수 위험 | 전역 변수 공유, 타입·테스트 없음 | 한 곳 고치면 다른 탭이 깨질 수 있음 |
| 탭 5개가 기능별로 흩어짐 | 기능을 붙일 때마다 탭 추가 | 메트로놈·드론·튜너를 왔다갔다 |

## 1. 핵심 컨셉
**"튜너 앱"이 아니라 "매일 여는 연습 파트너"**
- 켜면 바로 듣는다 (버튼 없음) — v1에서 좋았던 것 유지
- 한 화면에서 **튜닝 → 연습(박자·드론·음정) → 기록**이 자연스럽게 이어짐
- 손을 안 쓰는 조작 (음 패턴 명령), 광고·계정 없음, 오프라인

## 2. 화면 구성 (탭 5개 → 4개)
| 탭 | 내용 | v1에서 |
|---|---|---|
| **① 튜닝** | 현별 세로 테이프(현재 기본), 평균율/**순정 5도** 조율 전환, 탭하면 기준음 | 튜너 |
| **② 연습** | 하나의 화면에 **모듈을 켜고 끄는 방식**: 박자(메트로놈) · 드론 · 음정 게이지 · 연습 타이머. 예) 드론+게이지 = 음정 연습, 박자+게이지 = 스케일 | 메트로놈 + 드론 통합 |
| **③ 지판** | 조표·스케일, **자주 틀리는 음 히트맵**, 스케일 연습(다음 음 안내 + 음별 정확도) | 지판 |
| **④ 기록** | 오늘 목표 링, 12주 달력, 정확도 추이, 자주 틀리는 음 | 기록 |
| 설정 (시트) | 테마, 감도, 연주 명령, 백업 | 설정 |

첫 실행 **온보딩 30초**: 마이크 허용 → 주변 소음 자동 측정 → 테마 선택 → 끝

## 3. 디자인 시스템
- **토큰**: 색 · 글자 크기 · 간격 · 모서리 · 그림자 · 움직임 속도를 한 파일에 정의. 테마 = 토큰 묶음 (컴포넌트는 토큰만 사용)
- **테마 3종**: 테이프(다크) · 빈티지(황동/원목) · **라이트**(야외·무대 조명 아래 잘 보이게)
- **공용 부품**: Tape(가로/세로) · Dial · BrassPlate · Chip · Sheet · Gauge · BeatDots — 한 번 만들어 모든 탭에서 재사용
- **접근성**: 빨강/초록만으로 구분하지 않기(▲▼ 모양 병행, 색약 대비), 터치 영역 최소 48px, 진동 피드백
- **시그니처 효과 "울림"**: 음정이 맞을수록 물결(맥놀이)이 잔잔해짐 — 튜닝·드론·게이지 공통

## 4. 기술 구성
| 영역 | v1 | v2 |
|---|---|---|
| 코드 | JSX를 폰에서 변환, 전역 공유 | **Vite + React + TypeScript**, CI에서 미리 빌드 → 앱 시작 빠름 |
| 스타일 | Tailwind CDN | **빌드 시 CSS 생성** → 완전 오프라인 |
| 음정 분석 | 화면 스레드 | **AudioWorklet(오디오 전용 스레드)** → 바늘 끊김 없음, 지연·배터리 개선 |
| 상태 | 훅 + 전역 | 작은 스토어(zustand) + 기능별 모듈 |
| 저장 | localStorage | localStorage (하루 요약 약 1KB → 1년 400KB라 충분해서 IndexedDB 대신 유지) + 백업 내보내기/가져오기 |
| 테스트 | 없음 | **합성 음원으로 음정 검출 자동 테스트** (G현·옥타브·잡음 케이스), CI에서 매번 실행 |
| 미리보기 | APK만 | push마다 **APK + 웹 미리보기 주소** (설치 없이 브라우저로 확인) |
| 안드로이드 | WebView 껍데기 | 그대로 유지 (빠른 반복 개발에 유리) |

폴더 구조
```
src/
  audio/      pitch-worklet.ts, detector.ts, synth.ts(기준음·드론·클릭)
  features/   tuning/ practice/ fingerboard/ log/ commands/
  ui/         tokens.ts, themes/, components/(Tape, Dial, Plate…)
  store/      settings.ts, practiceLog.ts (IndexedDB)
tests/        detector.test.ts (합성 음원)
```

## 5. 기능 우선순위
1. **필수**: 튜닝(현별 테이프·순정 5도), 감도 자동 보정, 연습 화면(박자+드론+게이지), 기록(시간)
2. **차별화**: 음정 정확도 기록 + 지판 히트맵, 연주 명령, 스케일 연습
3. **확장**: 연습 녹음 → 음정 그래프로 다시 보기, 점진 템포(N마디마다 +BPM), 백업, 연습 알림

## 6. 진행 방식
- 브랜치 `v2`에서 개발, **앱 ID를 따로**(`com.etaeho.violintuner.v2`) → 폰에 v1과 v2를 **동시에 설치해 비교**
- 데이터: 앱 ID가 다르면 안드로이드가 저장 공간을 분리하므로, **나란히 설치된 동안에는 v1 기록을 자동으로 못 가져옴**. v2가 원래 앱 ID로 v1을 교체하는 5단계에서 v1 저장값(`vt.*`)을 읽어 v2 형식으로 옮김
- 단계 (각 단계마다 설치 가능한 APK)
  1. 뼈대: Vite+TS, 토큰·테마, CI(APK+웹 미리보기), 탭 4개 빈 화면
  2. 오디오 엔진: AudioWorklet 음정 검출 + 자동 테스트 → 튜닝 탭
  3. 연습 탭: 박자·드론·게이지 모듈
  4. 지판·기록 (정확도·히트맵)
  5. 온보딩, 라이트 테마, v1 데이터 이전, 다듬기 → v1 교체
